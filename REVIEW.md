# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Unconditionally returns `{"status": "ok"}` with 200 without checking if MongoDB is reachable. | Stop MongoDB service; `GET /health` still returns 200 OK instead of 503 Service Unavailable. | Added `client.admin.command("ping")` inside a `try/except` block, raising `HTTPException(503, "Database unavailable")` on failure. |
| 2 | Startup / Indexes (lines 20-27) | No indexes were created at startup. Leaves the app vulnerable to race conditions (duplicate `emp_code`, duplicate attendance for same date) and full collection scans (COLLSCAN) on 100k records. | Send two concurrent `POST /employees` or `POST /attendance/punch-in` requests; duplicate documents get inserted. `explain()` query plans show `COLLSCAN`. | Created `init_indexes()` called via FastAPI `lifespan` context manager on startup to idempotently create unique indexes on `employees.emp_code`, `attendance_logs.(emp_code, date)`, and compound indexes for filtering/sorting. |
| 3 | `compute_late_minutes` (lines 51-56) | Integer-truncates minutes before comparison `minutes > 10`, which fails Rule R2 on boundary cases. Also assumes punch-in is on the same calendar date without timezone awareness, failing on overnight shifts. | For shift `09:30`, punch-in at `09:40:01` (10m 1s) truncates to 10 minutes, making `10 > 10` evaluate to `False` and returning `0` instead of `10`. | Calculated difference in seconds in IST against the shift start on the attendance date; if `diff_sec > 600`, returned `int(diff_sec // 60)`, else `0`. |
| 4 | `compute_work_hours` (lines 58-60) | Used Python's built-in `round(..., 2)` which performs banker's rounding (round-half-to-even) instead of round-half-up mandated by Rule R4. | 9,630 seconds of work equals `2.675` hours. Built-in `round(2.675, 2)` gives `2.67` instead of `2.68`. | Used Python's `decimal.Decimal` with `ROUND_HALF_UP` quantized to `0.01`. |
| 5 | `compute_overtime` (lines 62-66) | Returns any positive minutes without enforcing Rule R3's 30-minute threshold; also evaluates overnight shifts on the wrong calendar day. | Staying 15 minutes late returns `15` instead of `0`. For a `22:00 - 06:00` overnight shift, punching out at `06:40` the next day evaluates shift end on day 1 (16 hours in the past) instead of day 2. | Added 1 day to the shift end date for overnight shifts (`shift_end <= shift_start`), and returned whole minutes only if `>= 30`, otherwise `0`. |
| 6 | `list_employees` (line 93) | Pagination skip formula used `skip = page * page_size`. On `page=1, page_size=20`, `skip=20`, skipping the first 20 employees entirely. | Calling `GET /employees?page=1` returned an empty list `[]` even though 6 employees were seeded. | Corrected the formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` (line 94) | `total` count used `count_documents({})` with an empty filter, ignoring the `department` query parameter. | Calling `GET /employees?department=Engineering` returned `total: 6` (entire company) instead of `total: 2` (filtered department size), violating Rule R10. | Updated count to `db.employees.count_documents(q)`. |
| 8 | `list_employees` (line 95) | Missing sort order; documents were returned in arbitrary MongoDB insertion order instead of ascending `emp_code`. | In a collection of unsorted employees, `items` order was non-deterministic and failed contract verification. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 9 | `create_employee` (lines 79-83) | Check-then-insert pattern (`find_one` then `insert_one`) was vulnerable to race conditions under concurrent requests. | Two simultaneous requests with the same `emp_code` both pass `find_one()` and cause an unhandled `DuplicateKeyError` (HTTP 500) on the second insert. | Wrapped `insert_one` in `try/except DuplicateKeyError` to cleanly return HTTP 409 Conflict. |
| 10 | `create_employee` / `EmployeeIn` (lines 53-61, 82) | `created_at` was set as naive local datetime and serialized as an ISO string instead of integer epoch milliseconds. Also lacked validation for `shift_start != shift_end` (spec line 119) and string pattern constraints. | Passing `shift_start="09:00", shift_end="09:00"` was accepted with 201 instead of rejected with 422. `created_at` in responses was a string, violating the `EpochMillis` schema. | Added regex validations and a model validator ensuring `shift_start != shift_end`; converted `created_at` to epoch milliseconds using `to_epoch_ms()`. |
| 11 | `punch_in` (line 101) | Did not check if `emp_code` exists. Attempting to subscript `emp["shift_start"]` when `emp` is None raised an unhandled `TypeError` (HTTP 500) instead of HTTP 404. | Sending a punch-in for an unregistered employee code returned HTTP 500 Internal Server Error. | Added check `if not emp: raise HTTPException(404, "unknown employee")`. |
| 12 | `punch_in` (lines 102-103) | Used local machine date/time instead of IST (+05:30) and did not handle overnight shift attribution per Rule R1 (early-morning punches belonging to the shift that started on the previous day). | For a 22:00 - 06:00 shift, an employee punching in at 00:05 was assigned the current date instead of yesterday's attendance date. | Converted timestamps to IST and implemented `get_attendance_date` applying Rule R1's overnight shift logic. |
| 13 | `punch_in` (lines 104-105) | Check-then-insert was vulnerable to race conditions under concurrent requests. | Sending two simultaneous punch-in requests for the same date resulted in an unhandled `DuplicateKeyError` (500) on the second request. | Wrapped insertion in `try / except DuplicateKeyError` returning HTTP 409 Conflict. |
| 14 | `punch_in` / `PunchInIn` (lines 63-67) | Accepted any arbitrary status string (defaulting to PRESENT). OpenAPI contract specifies only `PRESENT`, `WFH`, and `ON_DUTY` are allowed. | Clients could punch in with status `ABSENT` or `LEAVE` or invalid text without validation. | Constrained `status` to `Literal["PRESENT", "WFH", "ON_DUTY"]` in the Pydantic model. |
| 15 | `punch_in` and `list_attendance` (lines 119, 149) | Injected MongoDB's internal `_id` as an `id` field and returned raw datetime objects instead of integer epoch milliseconds. | Returned payload violated the `AttendanceRecord` schema (which has no `id` field and requires `EpochMillis` for `punch_in`/`punch_out`). | Created `format_attendance_doc` mapping fields without `id` and converting all instants to epoch milliseconds. |
| 16 | `list_attendance` (lines 144-147) | Loaded all matching records into Python memory with `list(...)` and sorted in Python; lacked secondary sort by `emp_code` ASC and did not validate `date_from > date_to` (422). | On 100,000 records, loading the full dataset into memory causes OOM/timeouts. Inverted date ranges returned 200 instead of 422. | Pushed sorting (`[("date", -1), ("emp_code", 1)]`), pagination, and filtering directly into MongoDB using the compound index; added date range validation raising HTTP 422. |

Also note anything you looked at and decided was **not** a defect, and why.
- **`load_dotenv()` placement**: Evaluated whether loading `.env` conflicts with the requirement that "real environment variables must take priority". In `python-dotenv`, `load_dotenv()` defaults to `override=False`, meaning existing OS environment variables injected by the test runner always take precedence over the `.env` file.
- **Storing dates and shift times as plain strings**: Examined whether `date` (`YYYY-MM-DD`) and `shift_start`/`shift_end` (`HH:MM`) should be converted to BSON datetimes in MongoDB. Confirmed per `DATA_MODEL.md` Section 1 that they are intentionally plain strings to avoid forcing UTC timezone shifts on pure calendar values.
- **Absence of multi-document transactions for punch-in / punch-out**: Evaluated whether transactions (`client.start_session()`) were required. The unique compound index on `(emp_code, date)` and single-document atomic update operations (`find_one_and_update`) provide full ACID guarantees for concurrent operations without imposing a replica set requirement.
